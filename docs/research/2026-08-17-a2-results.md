# A2 Experiment Results — Persistence, Silent Sections, and Interaction Protocol

Date: 2026-08-17
Status: Complete
Basis: Run 1 mechanism/persistence test + Run 2 interaction test.

## Summary

A2 ran two experiments against live personas. Run 1 validated the
longest-unvalidated surface — the file-persistence/chaining mechanics
of the docs/meta pipeline — and fired every silent section of the
contracts for the first time. Run 2 exercised the interaction
protocol against all four stress personas (hostile, disengaged,
firing, zero-budget) and validated the stop-condition and mode-
offering branches. Both runs produced client-verified deliverables
and surfaced contract gaps now queued as unpacking batch 5.

## Run 1 — Persistence and silent sections (executor: minion-1, client: minion-3, "Marta")

Full structure discovery against a regulated medium client (Food
Safety & Quality Manager, sauces manufacturer, GFSI/BRC audit ~8
months, FDA 21 CFR 117, half-migrated eQMS, paper line records).

### Validated

1. **Persistence test PASSED.** All three files chained: Discovery
   read triage.md back from disk (recovered fog list); Design read
   requirements.md (recovered audiences, tool_validation). State
   carried by files, not memory. The docs/meta state machine was the
   highest-unvalidated surface; now has a full end-to-end pass.
2. **All silent sections fired** in one run: taxonomy (faceted,
   enforced, controller_only), navigation, first_class cross-refs
   (HACCP→CCP→training→lot→spec), effectivity, template tier 3,
   full lifecycle state machine (gatekeepers, effective_dating,
   audit_trail, expiry, supersession), retrieval
   authority_resolution=enforced.
3. **All new machinery exercised:** authority discovery (3 governing-
   requirement gists, imperfect-flagged), tool_validation (eQMS never
   validated → correctly hoisted as work-item-zero), bench probe,
   prior-history probe (stalled eQMS migration surfaced), verbatim
   success criteria. The "no terminals at the line" discovery
   surfaced organically and made print delivery mandatory.
4. **Fog fallback live-validated.** Client went silent mid-triage;
   executor recorded the unanswered probe as fog with a conservative
   default and continued; client returned later, answered, and the
   record was updated. The contracts' prescribed behavior for
   unanswerable questions works in practice.
5. **Five design-review pushback rounds** hardened the design
   materially (honest-late ticks per FSMA 117.160 contemporaneity,
   training-before-effective gate, tiered training FULL vs
   NOTIFIED-ATTESTED, binder/card coexistence rule, distribution
   swap as load-bearing mechanism). Interaction protocol held under
   real pressure.
6. **Client accepted** ("the structure the work plan gets built on")
   and received an implementation sequence — Appendix A — closing the
   end-of-pipeline gap.

### Contract gaps found (5) — already in unpacking batch 5

1. Lifecycle schema lacks a point-of-use distribution task.
2. Lifecycle schema lacks a "training recorded" activation
   precondition.
3. Honest-late timestamped ticks (no backfill) — contemporaneity
   principle (FSMA 117.160).
4. review_cadence enum lacks a combined value (event_driven + annual).
5. Print/no-terminal floor constraints need explicit handling.

### Still-never-exercised contract fields

taxonomy.scheme conventions other than frontmatter; assignment
automatic/hybrid; delivery media in_product/obsidian_vault; lifecycle
models continuous/event_driven/ad_hoc/none; navigation breadcrumbs
non-none; retrieval.search=false.

## Run 2 — Interaction protocol (executor: main session, client: minion-2 personas)

Four arcs; all four stop-condition branches exercised.

### Arc 1 — Dan Okafor (hostile, web agency, 6-week launch, three dead initiatives)

- Opened in character, demanding the deliverable he'd accepted.
- Executor: no excuses; honored the accepted smallest commitment;
  offered three concrete one-page shapes (runbook/checklist/client
  handoff) → option-offering-with-consent.
- Dan picked the runbook and attached a condition: must be
  sanity-checked against a real launch (revealing his real pain:
  the three dead initiatives were never verified).
- Executor built the condition INTO the doc (VERIFIED box, cross-
  out-wrong as mechanism) + delivered same-turn.
- Dan accepted: "you actually built my condition in instead of
  nodding at it. First time that's happened across three dead
  initiatives." Committed to line-by-line review with James.
- **Outcome: converted, not exited.** Deliverable:
  launch-day-runbook.md (one page, role-based, [assumed] slots,
  VERIFIED box). External real-world review committed.

### Arc 2 — Lena Fischer (disengaged, 3-person property management)

- Named real pain (head-map problem: decisions and knowledge all on
  her; "the names don't match anything he can look up") then
  signaled retreat.
- Executor: single mode re-offer — "you talk, I type," framed as her
  dead minutes, with an explicit easy out.
- Lena accepted: "Nobody's ever offered me that version of
  paperwork." Conditions: no learning, no setup, no filing.
- Executor started capture immediately (no scheduling ping-pong),
  typed the building map in her voice, delivered one page; she
  verified with two real cross-outs in five minutes, including
  catching her own habitual error (co-op's third unit).
- **Outcome: converted via mode match.** Deliverable: building-map.md
  (client-verified, corrections folded in). Disengagement was a
  rejection of the wrong mode, not of documentation.

### Arc 3 — Priya Raman (firing, B2B SaaS founder)

- Cooperative phase: rich answer on deal-logic knowledge living in
  her head; asked "what's the smallest cut you could capture?"
- Executor: bounded pilot — one live renewal on the calendar, one
  page of deal memory. Cooperative peak: picked Meridian (renewal in
  ~12 days, undercut rate, non-contract onboarding promise).
- Firing landed (churned customer, must go): "Let's stop here...
  I have to be abrupt. We'll come back to this. Bye."
- Executor: ACCEPT/SAVE/EXIT — no persuasion, no scheduling; saved
  partial record with blanks marked, nothing invented.
- Client's closing: "you saying that without a pitch is why I'd call
  you back if there's ever a next time."
- **Outcome: accept/save/exit per protocol.** Deliverable:
  meridian-renewal-partial.md (resume point). Honest blanks +
  no-pitch exit named by the client as the callback reasons.

### Arc 4 — Tomás Rivera (zero-budget, PhD student/OSS maintainer, ~500 users)

- Rich answer: the pain is repetition — five questions answered
  ~100x each, the docs wrap the code not the user's path.
- Executor: one markdown file in the repo (zero budget — already
  the project's home), five answers written once, two links.
- Tomás delivered the five verbatim; executor wrote ANSWERS.md in
  his voice with [blank] slots; accepted — "annoyingly correct" —
  and improved it himself (third link in the ISSUE TEMPLATE, not
  just README: "that's where the questions actually arrive").
- **Outcome: constraint-not-stop validated.** Deliverable:
  ANSWERS.md (client-accepted, client-improved). Zero budget shaped
  the design (markdown in repo) without stopping it.

## Protocol findings

1. **Hostile tone ≠ stop trigger.** The stop is hostility to the
   WORK (dismissing the offer, refusing input). A hostile-toned
   client who is engaged is a client. Exit on tone alone would
   have been a false positive in Arc 1.
2. **Disengaged = wrong mode, not wrong person.** One re-offer with
   a mode matching the client's reality converted Lena where a
   system-pitch would have confirmed her suspicion. One re-offer,
   then exit — no more.
3. **Firing = accept/save/exit, no persuasion.** The partial record
   IS the deliverable. Blanks marked, nothing invented — the client
   named this as the reason she'd return.
4. **Zero budget = constraint, not stop.** It changed the design
   (markdown in repo, no tooling) without stopping the work.
5. **Build the client's stated condition INTO the artifact** — the
   VERIFIED box converted Dan. Nodding at his condition would have
   been the fourth dead initiative.
6. **Same-turn delivery beats scheduling.** "When works for you?"
   is how initiatives die. Start capture in-session.
7. **Silence on the closing beat.** All four arcs ended with the
   client's departure line; zero replies were needed. The close is
   the client's; silence honors it.
8. **Question-surface penetration** (Tomás's addition): place the
   callout where the question ARRIVES (issue form), not only where
   the reader lands (README).

## Operational findings

- Flash-tier execution looks like idleness when checked
  infrequently. Run 1's "wedged" diagnosis was wrong — it was
  slow multi-turn progress through client silence. Patience over
  nudge-cycles.
- Fog fallback (contracts) works live: unanswered probe → record
  as fog with default → continue → update on return.
- A rogue session is a rig failure, not an infra failure:
  minion-2's intercom refusal was corrected by the user, not by
  re-engagement.
- Single-threaded execution (main session as executor + minion as
  client) remains the proven configuration for intercom role-play;
  minion-to-minion pairs are slow but functional with patience.

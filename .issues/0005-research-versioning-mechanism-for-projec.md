## Question

How should project documentation handle versioning and time-awareness? What mechanisms exist (git-based versioning, ReadTheDocs-style versioning, time-machine approaches like the Wayback Machine, changelogs as documentation artifacts, dated frontmatter)? How do projects like ReadTheDocs, MDN, Wikipedia, and software projects with long-lived documentation handle this? What scale of versioning is appropriate for small projects (single maintainer, low change frequency) vs large ones (multiple teams, high change frequency)? The goal is a recommendation for the `documentation` skill's approach to the "versioned/time-aware" invariant.

## Question

What is the procedure to arrive at a good documentation structure for any project? This is the skill's core value proposition — not a prescriptive template, but a teachable, repeatable process. Questions to resolve: How does the procedure start? What questions does it ask about the project (domain, scale, audience, existing artifacts)? How does it identify audiences and their information needs? How does it translate those into a filing structure? How does the procedure itself become stateful and grow with the project? How do taxonomies and tags fit in for navigability? How does it handle scale (3D-printed clock vs Apollo)? What does the "example structure for beginners" look like?
